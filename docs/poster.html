01 · Implemented workflow

From failure to evidence

  1. Generate legal inputs within an explicit problem contract.
  2. Compare outputs with the reference; cross-check Dijkstra with a second oracle.
  3. Replay and reduce while preserving the observed failure.
  4. Record real Python events and bounded state snapshots.
  5. Reveal staged hints with claim and event references.

Hypothesis supplies generation and shrinking. Random testing is a baseline. No LLM or cloud service is required.

06 · Claims and limits

Feasibility within a small scope

Repeated seeds are not independent programs or learners. All eight sources were reviewed; there is no blinded holdout or student dataset. Semantic diagnosis covers two authored fixtures. No learning benefit, general root-cause accuracy or globally minimal witness is established.

Local trusted-code prototype. The runner is not a hostile-code sandbox. Failure not found means inconclusive, not correct. Conference acceptance and publication are external decisions.

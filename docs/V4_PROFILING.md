# قياس زمن البلوكات والأسطر في V4

هذه إضافة لقياس تنفيذ Python الحقيقي في عامل V4، ويمكن استخدامها مع حل صحيح أو خاطئ. اختر حزمة معتمدة، ألصق الكود، راجعه، وأدخل حالة JSON قانونية ثم اضغط «قياس زمن البلوكات على هذا المدخل». عند ترك المدخل فارغاً يستخدم أول اختبار معروف في الحزمة. القياس المستقل لا يبحث عن فشل ولا يدّعي إعادة شاهد ثلاث مرات.

البحث عن خطأ يضيف القياس تلقائياً إلى إعادة تنفيذ الشاهد. الطالب والمرجع يقاسان بصورة مستقلة على المدخل نفسه. يمكنك تبديل المسار، فرز البلوكات أو الأسطر، اختيار الساعة والتكلفة، الضغط على صف لتحديد البلوك في الكود، وتصدير CSV أو دليل JSON.

## معنى الأرقام

| الحقل | المعنى |
|---|---|
| Wall | زمن فعلي من `perf_counter_ns`؛ يتضمن الانتظار وتقييد CPU في الحاوية |
| CPU | وقت المعالج للعملية من `process_time_ns`؛ لا يحتسب النوم |
| Self | الوقت المنسوب إلى هذا السطر أو البلوك، مع استبعاد تنفيذ دوال Python المتتبعة المستدعاة منه |
| Inclusive | يشمل وقت الدوال المتتبعة المستدعاة أثناء بقاء السطر أو البلوك على المكدس |
| hits | زيارات السطر أو تفعيل الدالة/الموديول أو زيارات رأس البلوك؛ للحلقة قد يتضمن الفحص النهائي |
| المتوسط | الإجمالي مقسوماً على hits؛ ليس تلقائياً متوسط زمن جسم دورة واحدة |
| execution_wall_ns / execution_cpu_ns | قياس التنفيذ الكامل داخل العامل، ويشمل كلفة التتبع والترجمة المحلية |
| callback_wall_ns / callback_cpu_ns | كلفة callback الخاصة بالقياس واللقطات؛ مستبعدة من مقاطع الوقت المنسوبة للأسطر |
| elapsed_ms | زمن العملية من المضيف شاملاً بدء الحاوية والتنفيذ والاتصال والتنظيف |

عند وصول حدث تتبع، يُنسب الفرق منذ مغادرة callback السابقة إلى السطر النشط قبل معالجة اللقطة الجديدة. يوقف احتساب مقاطع الكود أثناء callback نفسها. تُنسب المقاطع أيضاً إلى البلوكات التركيبية النشطة في كل إطار؛ لذلك تتداخل أزمنة البلوكات المتداخلة والاستدعاءات الذاتية الشاملة. لا تجمع صفوف Inclusive كأنها أجزاء منفصلة. استدعاء مكتبة غير متتبعة يُحتسب ضمن السطر الذي استدعاها؛ لا يوجد تحليل داخلي للمكتبة.

## النطاق والحدود

- البلوكات: الموديول، الدوال، `for` و`while` و`if` و`with` و`try` و`match` ضمن ربط نطاقات الدوال المدعوم. لا يوجد تقسيم أدق من السطر الفيزيائي، أو وعد بتحليل شامل للكلاسات وcomprehensions والخيوط والبرامج غير المتزامنة.
- القياس لإطار التنفيذ الرئيسي في Python. عمليات أو خيوط فرعية لا تصبح تلقائياً بيانات قياس للأسطر. وقت CPU للعملية قد يشمل خيوطاً أخرى إذا أنشأها البرنامج؛ لا تستخدمه كقياس دقيق متعدد الخيوط.
- حد 100000 حدث قياس، 384 صف توقيت إطار/سطر، 128 بلوك و6000 عقدة AST. عند بلوغ حد القياس أو توقف التنفيذ بخطأ أو مهلة تكون الحالة `partial`، ولا تُقدَّم كقياس كامل.
- حد لقطات التتبع مستقل: قد يكون الرسم مبتوراً والقياس المجمع كاملاً. لا ينشئ ذلك أحداث رسم غير مسجلة؛ الانتقال إلى بلوك غير موجود في اللقطات يعرض تفسيراً صريحاً.
- حالة `disabled` في عمليات البحث دون تتبع. دليل تاريخي دون قياس يظهر `unavailable` بدلاً من أزمنة مخترعة. صفر زيارات يعني عدم رصد تنفيذ البلوك، وليس أن زمنه سالب أو مفقود.
- هذه أزمنة **أثناء التتبع**. استبعاد callback لا يزيل تأثير التتبع على المفسر والذاكرة والـcache، ولا يزيل مشاركة الجهاز أو حدود الحاوية (حالياً 0.5 CPU و128 MiB). لا تقارنها مباشرة بمهلة Codeforces، ولا تستنتج Big-O من مدخل واحد.
- البيانات من عامل التنفيذ وتبقى ملاحظات ضيف غير موثقة ضد كود عدائي. لا تتحول إلى دليل على السبب الجذري أو شهادة أمان.

## التحقق وإعادة التجربة

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests/test_v4_profiling.py backend/tests/test_v4_provider_schema.py -q
.\.venv\Scripts\python.exe tools/verify_v4_browser.py --out results/v4-profile-browser-new --port 8799
```

اختبارات القياس تشمل نسب الوقت الحتمية بين الأب والابن، النوم مقابل CPU، الحلقات والاستدعاء الذاتي والإطار المعاد استخدامه، الأخطاء وحدود القياس، التتبع المبتور، الأدلة القديمة، وحماية API من التشغيل دون مراجعة أو بمدخل غير قانوني. فحص المتصفح يتضمن القياس للكود الصحيح وCSV وربط المصدر والمهلة والموبايل والإلغاء.

تعريف الأحداث والساعات: [Python sys.settrace](https://docs.python.org/3.12/library/sys.html#sys.settrace)، [Python time](https://docs.python.org/3.12/library/time.html). التنفيذ يعتمد على عقد line-before-execution والساعات المنفصلة للزمن الفعلي وCPU؛ القيود أعلاه تخص تطبيق AlgoXRay.
